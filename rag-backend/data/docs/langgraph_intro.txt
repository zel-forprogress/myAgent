LangGraph 是一个用于构建 Agent 工作流的编排框架。

在本项目中，LangGraph 计划用于第二阶段的 Agent 流程编排。第一阶段我们已经使用 FastAPI、LangChain、Milvus、DashScope 和 Qwen 跑通了后端 RAG 闭环。这个闭环包括文档读取、文本切分、向量化、向量写入、相似度检索、上下文拼接和大模型回答。第一阶段的目标是证明知识库问答链路可以正常工作，而第二阶段的目标是让这条链路变得更加可控、可扩展和可观测。

普通 RAG 流程通常是固定的。用户提出问题后，系统直接把问题转成向量，然后从向量数据库中检索相关文本片段，再把这些片段拼接到 Prompt 中，最后调用大模型生成回答。这种方式简单直接，适合最小可行版本。但是当系统需要处理更复杂的任务时，固定链式流程就不够灵活。例如，系统可能需要先判断用户的问题是否需要检索知识库，或者判断检索结果是否足够可靠，还可能需要在答案生成之后做一次质量检查。如果回答质量不够好，系统还需要重新检索或重新生成答案。

LangGraph 的价值就在这里。它可以把一个 Agent 的执行过程拆分成多个节点，每个节点负责一个明确的任务。例如，问题分析节点负责理解用户意图，检索决策节点负责判断是否需要访问知识库，知识库检索节点负责从 Milvus 中查找相关片段，答案生成节点负责调用 Qwen 生成回答，结果检查节点负责判断回答是否满足要求。不同节点之间通过状态进行连接，状态中可以保存用户问题、检索结果、生成答案、错误信息和执行历史。

相比普通的链式调用，LangGraph 更强调状态管理和流程控制。它支持条件分支，也支持循环执行。例如，当检索结果为空时，流程可以进入问题改写节点，让模型把用户问题改写成更适合检索的形式，然后重新执行检索。当生成的答案缺少引用依据时，流程可以回到检索节点，扩大 top_k 或换一种检索策略。当系统发现用户问题不需要查知识库时，也可以直接走普通聊天节点，而不是每次都固定执行 RAG。

在企业知识库 Agent 项目中，LangGraph 可以承担几个核心职责。第一，它负责管理 Agent 的执行状态。第二，它负责控制不同节点之间的流转。第三，它负责根据条件决定是否检索知识库。第四，它负责在结果不理想时触发重试或修正。第五，它可以为后续接入工具调用、MCP 协议和人工审核打基础。这样一来，系统就不再只是一个简单的问答接口，而是一个可以不断扩展的 Agent 工作流。

本项目后续可以将当前的 /chat 接口改造成一个 LangGraph workflow。用户请求进入系统后，首先进入 question_analyzer 节点。这个节点会判断问题类型，例如知识库问答、闲聊、任务执行或无法处理的问题。如果是知识库问答，就进入 retriever 节点，从 Milvus 中检索相关 chunks。如果检索结果为空，就进入 rewrite_query 节点，对问题进行改写后再次检索。如果检索结果足够好，就进入 answer_generator 节点，调用 Qwen 生成答案。最后进入 answer_checker 节点，对答案是否基于上下文、是否有引用来源、是否回答了问题进行检查。

引入 LangGraph 后，系统的可维护性会更好。每个节点都可以单独测试，也可以单独替换。例如，未来如果要把检索策略从单纯向量检索升级成混合检索，可以只修改 retriever 节点。如果要增加重排模型，可以在 retriever 和 answer_generator 之间增加 reranker 节点。如果要接入 MCP 工具调用，可以增加 tool_router 节点，让系统判断是否需要调用外部工具。如果要加入人工确认，可以在关键节点后加入 human_review 节点。

LangGraph 也适合和观测系统结合。后续接入 Langfuse 后，可以记录每个节点的输入、输出、耗时、token 消耗和错误信息。这样当回答质量不好时，可以定位问题到底出在检索阶段、Prompt 阶段还是模型生成阶段。对于生产级 Agent 系统来说，流程可观测性非常重要，因为 Agent 的行为不是简单的函数调用，而是由多个步骤共同决定的。

总的来说，LangGraph 在本项目中的定位是 Agent 编排框架。它不会替代 Milvus，也不会替代 LangChain 的 RAG 组件。Milvus 负责存储和检索向量，LangChain 负责连接模型、Prompt 和基础 RAG 组件，而 LangGraph 负责控制整个 Agent 的执行流程。三者的关系可以理解为：Milvus 是知识存储层，LangChain 是大模型应用组件层，LangGraph 是 Agent 流程编排层。

本项目第一阶段已经完成了基础 RAG 闭环。接下来引入 LangGraph 的意义，是把这个固定流程升级成可编排流程，让系统具备更强的决策能力、恢复能力和扩展能力。这也是从简单 RAG 应用走向 Agent 系统的重要一步。
